## 3. 블럭 크기 대비 간격 벤치마크 재확인

### 현재 상태
- `src/render/Renderer.js:75` — `this._hexSize = Math.min(w, h) * 0.85 / gridDiameter / Math.sqrt(3)`
- `hexToPixel()` (라인 93-96): `1.5 * q` 및 `sqrt(3) * (r + q/2)` → 간격 없이 타일이 맞닿음
- `src/render/HexCellView.js` — `drawHexagon()`에서 `size` 그대로 사용 (패딩/갭 없음)

### 벤치마크 비교
벤치마크 이미지에서는:
- 타일 간 **약간의 간격(gap)** 존재 (검은색 배경이 보임)
- 타일 크기 대비 약 **3-5% 축소**된 inner radius로 그리기
- 현재 구현은 hexSize를 그대로 사용하여 타일끼리 완전히 밀착

### 구현 방안
`HexCellView.js`의 `drawCell()`과 `drawEmptyCell()`에서 실제 그리기 크기를 `size * GAP_FACTOR`로 축소:

```js
const GAP_FACTOR = 0.92; // 8% 간격
const drawSize = size * GAP_FACTOR;
drawHexagon(ctx, cx, cy, drawSize);
```

또는 `Renderer.js`에서 hexToPixel 좌표는 유지하되, 렌더링 시 전달하는 hexSize를 축소:
```js
const renderSize = this._hexSize * 0.92;
drawCell(ctx, x + offX, y + offY, renderSize, cell.value, { ... });
```

### 수정 파일
| 파일 | 변경 내용 |
|------|----------|
| `src/render/Renderer.js` | `_drawBackground()`, `_drawTiles()`에서 렌더링 사이즈에 갭 팩터 적용 |
| 또는 `src/render/HexCellView.js` | `drawCell()`, `drawEmptyCell()`에 `gapFactor` 상수 추가 |

### 주의사항
- `pixelToHex()` 히트 판정은 기존 hexSize 유지 (터치 영역은 줄이지 않음)
- 간격 비율은 벤치마크 이미지 비교하여 미세 조정 필요

## 4. 병합시 단계별 병합 애니메이션

### 현재 상태
- `src/core/MergeSystem.js` — BFS로 전체 연결 그룹을 한 번에 찾고, 즉시 `clear()` + `setValue()`
- `src/main.js:177-206` — merge 이벤트 시 모든 `mergedCoords`를 동시에 `playMergeAnimation()`으로 이동
- `MergeResult`에 `depthGroups`(깊이별 좌표 그룹)과 `stepValues`(단계별 중간값)가 이미 존재
- 하지만 **단계별 순차 실행은 미구현** — 모든 셀이 동시에 tapCoord로 이동

### 벤치마크 비교
벤치마크 앱(동영상 `res/KakaoTalk_20260205_210028358.mp4`)에서는:
- depth 순으로 가장 먼 셀부터 순차적으로 타겟 셀로 이동
- 각 depth 그룹이 이전 그룹의 애니메이션 완료 후 시작
- 단계마다 타겟 셀 값이 중간값으로 업데이트 (예: 2→4→8→16)

### 구현 방안

#### A. MergeSystem 분리: 로직 vs 애니메이션
현재 `tryMerge()`가 즉시 셀을 clear/setValue하므로, 애니메이션과 동기화가 불가능.

**1단계: MergeSystem 수정**
- `tryMerge()`에서 `cell.clear()`/`cell.setValue()`를 **즉시 실행하지 않도록** 옵션화
- 또는 별도 `prepareMerge()` → `MergeResult` 반환 (셀 변경 없음) + `applyMerge(result)` (셀 변경)

**2단계: GameManager에서 단계별 실행**
```js
async handleTap(coord) {
    const result = this.mergeSystem.prepareMerge(coord);
    if (!result) return;

    this._setState(GameState.ANIMATING); // 입력 차단

    // depthGroups: deepest-first (가장 먼 곳부터)
    for (let i = 0; i < result.depthGroups.length; i++) {
        const group = result.depthGroups[i];
        const stepValue = result.stepValues[i];

        // 이 depth 그룹의 셀들을 타겟으로 이동 애니메이션
        await animator.playStepMerge(group, result.tapCoord, stepValue);

        // 중간값으로 타겟 셀 업데이트 (시각적)
        tapCell.setValue(stepValue);

        // 이동한 셀들 clear
        group.forEach(coord => grid.getCell(coord).clear());
    }

    // 최종 점수 + 이펙트
    this.score.addScore(result.scoreGained);
    this._dispatch('merge', { result });

    // refill + 게임오버 체크
    ...
    this._setState(GameState.PLAYING);
}
```

**3단계: TileAnimator에 `playStepMerge()` 추가**
- 기존 `playMergeAnimation()`과 유사하되, 한 depth 그룹만 처리
- parentMap을 활용하여 각 셀이 부모 셀 방향으로 이동하도록 경로 설정

#### B. 간소화 방안 (빠른 구현)
- BFS depth 그룹을 deepest-first로 순회
- 각 그룹마다 `Promise.all()` + `await` 딜레이
- 기존 MergeSystem은 그대로 두고, 시각적으로만 단계별 처리

### 수정 파일
| 파일 | 변경 내용 |
|------|----------|
| `src/core/MergeSystem.js` | `prepareMerge()` / `applyMerge()` 분리 (또는 deferred 옵션) |
| `src/game/GameManager.js` | `handleTap()` → async, 단계별 애니메이션 + apply 순차 실행, `ANIMATING` 상태 추가 |

### 영향 범위
