# 게임 UI 개선 상세설계

작성일: 2026-09-28  
요구사항 원문: `../untitled-2.md`  
상태: 구현 전 설계. 아래 권장 기본값은 확정된 사용자 선택과 구분한다.

## 1. 범위와 설계 가정

| 요구사항 | 이 문서의 권장 해석 | 완료 기준 |
|---|---|---|
| 다른 단위인 블럭 색 중복되지 않게 | 서로 다른 블록 숫자 값에는 서로 다른 기본색 사용 | 지원 범위 전체에서 색상 중복이 없고 인접 단계가 육안으로 구분됨 |
| 상단메뉴 좌우 균일하게 세로 정렬 | 제목 좌우 메뉴 영역의 너비와 외곽 여백을 동일하게 확보 | 메뉴 구성과 관계없이 제목이 콘텐츠 중앙에 위치 |
| 제목 가운데 정렬 | 게임 콘텐츠 영역의 가로 중심에 제목 배치 | 좌우 버튼 내용이 달라도 제목 중심 유지 |
| 왕관 변경시 사운드 고급화 | 실제 왕관 위치 또는 최고 값 변경 시 부드러운 차임 재생 | 초기화·복원에서는 무음, 실제 변경당 한 번 재생 |
| 점수표시에 단위 추가 | K/M/B/T로 자릿수를 축약하고 `점`·`pts` 접미사는 붙이지 않음 | 모든 점수 화면에서 동일한 규칙 적용 |

사용자 확인: 점수 표시는 자릿수를 줄이는 요구사항이다. K/M/B/T 축약을 사용하며 점수 접미사는 추가하지 않는다.

사용자 확인: 상단 메뉴 정렬은 제목을 가운데 배치하기 위해 좌우 공간을 동일하게 확보하는 의미다. 버튼을 세로 열로 재배치하는 요구사항은 아니다. 기존 메뉴 순서와 배치 방향을 유지한다.

## 2. 현재 코드와 적용 전제

- `src/render/HexCellView.js`: 블록 색상을 `getColor(value)`, 숫자를 `formatValue(value)`로 받아 그린다.
- `src/render/Renderer.js`: 획득 점수 팝업도 현재 `formatValue(popup.score)`를 사용한다. 점수 전용 포맷터로 분리할 지점이다.
- `src/game/GameManager.js`: `updateCrowns()`는 최고 값의 모든 블록에 왕관을 지정하고 호출마다 `crownchange`를 보낸다. 실제 변경 여부 판별이 필요하다.
- `docs/web-impl-tasks.md`: HUD의 좌측 사운드·다이아몬드, 우측 메뉴·도움말 및 기존 왕관 Cmaj7 효과음 계획이 기록되어 있다. 이는 계획 문서이며 현재 동작 확인을 대신하지 않는다.
- 현재 작업 트리에서 `index.html`, `src/ui/HUDManager.js`, `src/audio/ProceduralSFX.js`, `src/config/tileColors.js`, `src/core/TileHelper.js`, `src/main.js` 등은 삭제 상태다. 이 설계 작업은 삭제된 파일을 복구하거나 실행 가능하다고 가정하지 않는다. 구현 시작 시 실제 적용할 소스 기준을 먼저 확인한다.

## 3. 블록 색상

### 3.1 매핑 규칙

1. 게임이 지원하는 블록 값 목록을 병합·생성 규칙에서 확보한다. 현재 남은 파일만으로 최대 지원 값을 확정하지 않는다.
2. 값별 기본색을 고정 매핑한다. 같은 값은 화면·테마·게임 재시작과 관계없이 같은 기본색을 사용한다.
3. 배열 인덱스 나머지 연산으로 팔레트를 반복하지 않는다. 지원 값 목록과 색상 매핑 키 목록이 일치해야 한다.
4. 단순히 HEX 문자열만 다른 유사색으로 중복을 회피하지 않는다. 인접 단계는 색상과 명도 차이를 함께 검토한다.
5. 다크·라이트 테마에서는 주변 배경과 외곽선을 조절한다. 블록의 값별 색상 의미는 유지한다.

최종 색상표는 지원 단계 수 확인 후 확정한다. 무제한 단계에 대해 사람이 구분 가능한 고유 색상을 보장하지 않는다. 지원 범위를 늘릴 때 팔레트 검토를 함께 수행한다.

### 3.2 렌더링 계약

기존 `getColor(value)`의 반환 형식은 유지한다. 글자색이 추가로 필요하면 별도 `getTileTextColor(value)`를 제공한다. 숫자 라벨과 왕관은 색만으로 상태를 판별하지 않아도 보이도록 유지한다.

지원하지 않는 값은 개발 검증에서 오류로 보고한다. 운영 화면에서는 중립 배경·뚜렷한 외곽선·정확한 숫자로 표시하여 렌더링 중단을 피한다. 이 대체 표시를 정상 팔레트의 일부로 간주하지 않는다.

### 3.3 검증

- 모든 지원 값의 기본색 중복 및 누락 검사.
- 전체 단계 색상표를 한 화면에 렌더링하여 인접 단계와 멀리 떨어진 단계의 혼동 확인.
- 밝은/어두운 테마, 작은 블록, 왕관 표시, 합성 애니메이션에서 숫자 판독 확인.

## 4. 상단 메뉴와 제목

### 4.1 배치

게임 콘텐츠 컨테이너 안에 3열 헤더를 둔다. 좌우 메뉴 영역은 동일한 너비로 확장되고 중앙에는 제목을 배치한다.

```text
┌────────────────────────────────────────────────┐
│ [좌측 메뉴]       HEXA MERGE       [우측 메뉴]  │
│ ← 동일 너비 →                  ← 동일 너비 →  │
└────────────────────────────────────────────────┘
```

그림은 구성 관계를 나타낸다. 제목과 좌우 메뉴 영역의 세로 중심을 맞추되 메뉴 내부 배치 방향은 유지한다.

권장 기본값:

| 속성 | 값 |
|---|---|
| 헤더 좌우 내부 여백 | 16px, 360px 미만에서는 12px |
| 좌우 메뉴 영역 너비 | 동일한 1fr |
| 버튼 터치 영역 | 48 × 48px |
| 버튼 간격 | 8px |
| 제목과 메뉴 영역 사이 간격 | 8px |
| 제목 글자 크기 | 가용 폭에 따라 20~32px |
| 제목 줄바꿈 | 허용하지 않음 |

CSS Grid의 `minmax(0, 1fr) auto minmax(0, 1fr)` 구조와 `align-items: center`를 사용한다. 좌측 메뉴는 시작 가장자리, 우측 메뉴는 끝 가장자리에 정렬한다. 제목은 중앙 열에 둔다. 아이콘의 시각적 크기는 별도로 조정하되 터치 영역은 같다.

제목은 좌우 열의 폭이 같으므로 콘텐츠 영역의 정확한 가로 중앙에 위치한다. 재화 숫자가 길어져도 열을 넓히지 않는다. 숫자를 축약하거나 별도 재화 영역에서 표시한다. 버튼이 숨겨지는 경우 좌우 영역의 동일 너비는 유지하되 숨긴 버튼은 포커스 대상에서 제외한다.

### 4.2 반응형과 접근성

- 320px 이상에서 제목·버튼이 겹치지 않도록 제목 크기를 조정한다.
- 노치 등 안전 영역은 상위 컨테이너에서 반영하고, 중앙 정렬 기준은 안전 영역을 반영한 게임 콘텐츠 영역으로 통일한다.
- 아이콘 버튼에 접근 가능한 이름과 키보드 포커스 표시를 제공한다.
- 탭 이동 순서는 DOM 순서와 일치하게 구성한다.
- 200% 확대에서 공간이 부족하면 제목을 별도 첫 행으로 옮긴다. 좌우 메뉴 영역의 동일 너비는 유지한다.

### 4.3 완료 조건

320/360/390/768/1280px 화면 폭에서 제목 중심과 콘텐츠 중심의 차이가 1 CSS px 이내이고, 제목과 좌우 메뉴 영역의 중심 Y 차이도 1 CSS px 이내다. 긴 재화 표시, 사운드 아이콘 변경, 도움말 숨김 상태에서도 겹침이 없어야 한다.

## 5. 왕관 변경 감지와 효과음

### 5.1 변경 판정

이전 상태에 `highestValue`와 왕관 좌표 집합을 저장한다. 좌표는 객체 참조 대신 정규화된 `q,r` 키로 비교하며 배열 순서는 무시한다.

| 상황 | 화면 갱신 | 소리 |
|---|---|---|
| 새 게임·저장 복원·재시작 | 왕관 상태와 비교 기준 초기화 | 없음 |
| 최고 값·왕관 좌표 집합 모두 동일 | 필요 시 기존 갱신 유지 | 없음 |
| 최고 값 동일, 왕관 좌표 집합 변경 | 왕관 변경 반영 | 기본 차임 1회 |
| 같은 위치에서 최고 값 상승 | 숫자·왕관 갱신 | 상승 차임 1회 |
| 최고 값과 왕관 위치 모두 변경 | 왕관 변경 반영 | 상승 여부에 따라 차임 1회 |
| 최고 값 하락 후 다른 블록에 왕관 지정 | 왕관 변경 반영 | 기본 차임 1회 |
| 빈 보드로 전환 | 왕관 제거 | 없음 |

초기화·복원 여부는 값이 0인지로 추론하지 않고 명시적인 호출 사유로 전달한다. 합치기 중간 프레임이나 임시 보드 상태에서 소리를 발생시키지 않고 한 턴의 최종 왕관 상태에서 판단한다.

### 5.2 이벤트와 책임

기존 `crownchange` 이벤트와 `crownCoords`를 유지하여 시각 갱신 구독자를 깨뜨리지 않는다. 다음 필드를 추가하는 방향으로 설계한다.

```js
{
  crownCoords,
  previousHighestValue,
  highestValue,
  changed,       // 최고 값 또는 좌표 집합 변경
  reason,        // init | restore | merge | continue | reset
  playSound,     // 실제 변경 + 유효한 왕관 + 허용된 호출 사유
  soundVariant   // basic | upgrade
}
```

`GameManager`는 변경 사실과 재생 의도만 전달한다. 실제 재생은 이벤트 연결부와 오디오 모듈에서 담당한다. 음소거·음량·오디오 준비 상태는 오디오 모듈이 최종 적용한다.

연속 이벤트의 중복 재생 방지는 가능하면 턴 ID로 처리한다. 단순 시간 제한으로 정상적인 다음 턴의 변경음을 누락시키지 않는다. 새 게임과 복원 시 이전 비교 상태 및 재생 중인 왕관음을 정리한다.

### 5.3 음향 사양 — 청음 후 조정할 초깃값

- 기본음: C5–E5–G5–B5 계열의 부드러운 차임, 약 0.45초.
- 상승음: 기본음에 C6를 약하게 추가, 약 0.60초.
- 각 음의 시작을 25~40ms씩 분산하여 딱딱한 동시 발음을 줄인다.
- 어택 8~15ms, 이후 부드럽게 감쇠하며 끝부분은 0으로 페이드한다.
- 높은 배음은 기본음보다 약하게 두고, 출력 피크를 정규화한다.
- 왕관음은 동시에 한 개만 재생한다. 새 왕관음이 시작되면 이전 왕관음은 약 30ms 동안 페이드아웃한다.
- 병합음과 함께 들어도 왕관음이 과도하게 튀지 않도록 별도 게인을 둔다. 최종 음량은 모바일 스피커와 이어폰 청음으로 결정한다.
- 음소거 시 즉시 멈추고, 오디오가 준비되지 않은 상태에서는 건너뛴다. 이후 잠금이 해제되어도 지난 효과음을 뒤늦게 재생하지 않는다.

판정과 음원 재생을 분리해서 테스트한다. 실제 청음 전에는 “고급화 완료”로 판정하지 않는다.

## 6. 점수 표시

### 6.1 표기 규칙

블록용 `formatValue()`와 분리한 점수 포맷터를 둔다. 원본 숫자는 그대로 저장하며 화면 출력만 변환한다.

| 원본 점수 | 기본 표시 |
|---:|---|
| 0 | 0 |
| 999 | 999 |
| 1,000 | 1K |
| 1,250 | 1.2K |
| 999,999 | 999.9K |
| 1,000,000 | 1M |
| 1,250,000,000 | 1.2B |
| 1,000,000,000,000 | 1T |

축약 단위는 K=10³, M=10⁶, B=10⁹, T=10¹²로 고정한다. 소수 첫째 자리까지 내림하고 끝의 `.0`을 제거한다. 경계 직전 값이 다음 단위에 도달한 것처럼 표시되지 않게 한다. T 이상은 T를 유지하고 정수부에 쉼표를 사용한다.

전체 숫자 모드는 `1,250`처럼 천 단위 쉼표를 사용한다. DOM의 접근 가능한 이름에는 전체 숫자를 제공하고, 결과·통계 화면에서는 전체 점수도 확인할 수 있게 한다. 터치 환경에서 툴팁만으로 정확한 점수를 제공하지 않는다.

### 6.2 함수 계약과 적용 범위

```js
formatScore(value, { compact = true, signed = false } = {})
```

- 입력: 0 이상의 유한한 안전 정수. `signed`는 획득 팝업에 `+`를 붙이는 용도다.
- 비정상 값은 `—`로 표시하고 개발 검증에서 오류로 보고한다. 정상 점수 0으로 위장하지 않는다.
- Number 안전 정수 범위를 넘는 점수를 지원하려면 저장·계산 체계부터 별도 설계한다.
- 적용: 현재 점수, 최고 점수, 게임 종료 점수, 통계의 점수 항목, 리더보드 점수, 획득 팝업.
- 제외: 블록 값, 재화, 횟수, 시간.
- 팝업은 `formatScore(score, { signed: true })`를 사용하여 `+1.2K`처럼 표시한다. 호출부에서 `+`를 중복으로 붙이지 않는다.
- 단위까지 포함한 문자열 길이로 HUD 크기를 계산한다. 숫자에는 가능하면 고정 폭 숫자 스타일을 적용한다.

## 7. 변경 대상과 구현 순서

아래 경로 중 삭제 상태인 파일은 적용 소스 기준 확인 후 편집한다. 새 포맷터 파일명은 제안이다.

| 대상 | 작업 |

| `src/config/tileColors.js` | 지원 값별 고유 팔레트 정의, 반복 매핑 제거 |
| `src/render/HexCellView.js` | 숫자·왕관 대비와 테마 표시 확인 |
| `index.html`, `src/ui/HUDManager.js` | 대칭 헤더, 동일 너비 메뉴 영역, 중앙 제목, 점수 출력 |

| `src/render/Renderer.js` | 획득 팝업에 점수 포맷터 적용 |
| `src/game/GameManager.js` | 왕관 상태 비교, 호출 사유, 이벤트 필드 |
| `src/main.js` | 왕관 이벤트와 오디오 연결 |
| `src/audio/ProceduralSFX.js` | 차임 생성, 재생 제어, 음소거 처리 |
| 결과·통계·리더보드 UI | 점수 표기 통일 |

구현 순서는 소스 기준·지원 값 확인 → 포맷터와 팔레트 → 헤더 배치 → 왕관 판정 → 효과음 → 통합 검증이다. 게임 규칙·점수 계산·저장 형식 변경은 이 개선의 범위에 포함하지 않는다.

## 8. 검증 및 인수 조건

| 영역 | 핵심 검증 |
|---|---|
| 색상 | 지원 값 누락·중복 없음, 양 테마에서 숫자 식별 가능 |
| 배치 | 지정 화면 폭에서 제목 중앙·좌우 대칭, 긴 숫자 및 200% 확대 시 겹침 없음 |
| 점수 | 0/999/1,000/999,999/1,000,000 및 B/T 경계, 축약 단위·내림·부호 일관성 |
| 왕관 판정 | 동일 상태 무음, 동일 위치 값 상승 유음, 좌표 순서만 바뀐 경우 무음 |
| 생명주기 | 시작·복원·재시작 무음, 한 턴에서 복수 왕관이 바뀌어도 한 번만 재생 |
| 오디오 | 음소거, 연속 변경, 다른 효과음과 중첩, 오디오 미준비 상태 처리 |
| 데이터 | 표기 변경 전후 점수 계산과 저장 원본 동일 |

자동 검증은 점수 경계값·왕관 상태 전이·팔레트 완전성에 집중한다. 배치와 음질은 실행 화면 및 청음으로 확인한다. 현재 삭제된 진입점과 테스트 설정이 정리되기 전에는 실행 검증이 완료되었다고 기록하지 않는다.

## 9. 구현 전 확인할 제품 선택

추가 지시가 없으면 이 문서의 권장 기본값을 적용한다.

1. “다른 단위”를 서로 다른 블록 값으로 해석한다.
2. [사용자 확인] 좌우 메뉴 영역의 너비를 같게 확보해 제목을 중앙 정렬한다.
3. 제목은 게임 콘텐츠 영역을 기준으로 중앙 정렬한다.
4. 왕관 위치 변경에도 기본음을 내고 최고 값 상승에는 상승음을 낸다.
5. [사용자 확인] 점수는 자릿수를 줄여 표시한다. [권장 규칙] 접미사 없이 K/M/B/T를 사용한다.

지원 최대 블록 값과 실제 편집 소스 기준은 구현 시 확인해야 하는 기술 전제이며, 임의의 값으로 확정하지 않는다.

## 10. 구현 준비 조사 — 마지막 커밋 기준

현재 작업 트리의 삭제 파일을 복구하지 않고 `git show HEAD:<path>`로 조사했다. 아래는 마지막 커밋의 내용이며 현재 실행 상태를 뜻하지 않는다.

- `tileColors.js`는 16색을 사용하고 65,536을 넘으면 단계의 나머지 연산으로 같은 색을 반복한다. 다른 값의 색 중복 원인이 확인됐다.
- `TileHelper.js`의 `MAX_VALUE`는 `1e300`, `TOTAL_LEVELS`는 100이다. 실제 수치 범위는 100단계보다 크므로 16색을 조금 늘리는 것만으로는 전체 범위를 처리할 수 없다. 구현에서는 유효한 2의 거듭제곱 단계에 결정적인 고유 색상 생성 규칙을 적용하고, 자주 등장하는 인접 단계는 시각 검증한다. 전체 단계의 육안 구별 가능성을 보장하지는 않는다.
- 점수도 큰 Number를 사용할 수 있는 기존 구조다. 6절의 안전 정수 제한을 그대로 적용하면 기존 큰 점수가 `—`로 사라질 수 있다. 실제 적용 시 기존 점수 저장 범위와 호환하도록 유한한 비음수 Number를 받으며, 안전 정수 범위 밖에서는 원본의 정수 정밀도를 보장하지 않는다. T를 넘어서도 문자열을 짧게 유지하도록 추가 축약 단위 또는 지수 표기를 사용한다. 기존 점수의 값 자체는 변경하지 않는다.
- 기존 `formatValue()`는 `1e33`마다 단위를 순환시킨다. 점수 전용 포맷터는 이 동작을 재사용하지 않아 큰 점수가 작은 점수처럼 보이는 문제를 피한다.
- HUD는 좌측에 사운드 버튼 하나, 우측에 도움말·메뉴 버튼 두 개가 있다. 좌우 콘텐츠 수가 달라도 동일한 영역 너비를 확보해야 한다.
- 실제 게임 제목은 `XUP`이다. 4절의 HEXA MERGE 그림은 배치 예시이며 제목 문구를 변경하는 요구사항은 아니다. 구현 시 기존 `XUP`을 유지한다.
- `main.js`는 왕관 좌표가 하나라도 있으면 소리를 재생한다. 왕관 변경 판정과 이벤트 구독부를 함께 수정해야 불필요한 재생을 막을 수 있다.

이 조사로 확인된 큰 숫자 호환성 및 실제 제목에 관한 내용은 앞선 권장안보다 우선한다. 삭제된 웹 소스를 복구할지 또는 다른 소스에 적용할지는 사용자에게 확인을 요청한 상태다.
